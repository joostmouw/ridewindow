## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User free-text comment → mailto: URI → OS mail client | User-entered text crosses into a URI passed to an external app via `url_launcher` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-quick260714n0c-01 | Tampering | `buildFeedbackMailtoUri` | mitigate | Use Dart's `Uri(queryParameters: {...})` constructor (not string concatenation) so comment text is automatically percent-encoded — a comment containing `&`, `?`, `#`, or newlines cannot break the URI or inject extra mailto fields (e.g. `cc=`, `bcc=`). |
| T-quick260714n0c-02 | Information Disclosure | Feedback body (rating + comment) | accept | User-initiated, user-authored content sent via the user's own mail client to a single hardcoded developer address; no PII collected beyond what the user voluntarily types, no persistence, no network call from the app itself. |
| T-quick260714n0c-03 | Denial of Service | `canLaunchUrl`/`launchUrl` failure (no mail app configured) | accept | Guarded with `if (await canLaunchUrl(uri))` matching the existing `_launchPrivacyPolicy` pattern — silently no-ops rather than crashing; acceptable UX for a solo-dev hobby project, consistent with existing app behavior for other external links. |
</threat_model>
