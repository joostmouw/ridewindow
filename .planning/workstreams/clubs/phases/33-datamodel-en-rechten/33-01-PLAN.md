Sectie 9 — public.guard_group_member_insert() returns trigger; trigger group_members_guard_insert `before insert on public.group_members for each row`. Stappen: (1) lock de groepsrij met `perform 1 from public.groups where id = new.group_id for update` — serialiseert twee gelijktijdige joins op plek 30 (CONTEXT: Race); (2) neem `pg_advisory_xact_lock(hashtext(new.user_id::text))` zodat twee gelijktijdige joins van één persoon in twee verschillende groepen de 10-grens niet omzeilen; (3) als het aantal group_members-rijen van new.group_id ≥ 30 → group_full; (4) als het aantal group_members-rijen van new.user_id ≥ 10 → too_many_groups; (5) zet new.display_name uit profiles.user_name van new.user_id (kan null zijn); (6) zet new.joined_at := now() (opvolging draait op joined_at, dus die mag nooit van de client komen — dubbel slot naast de kolomgrant); return new. Commentaar: security definer is nodig omdat de aanroeper (bv. een beheerder die een maatje toevoegt) de andere lidmaatschappen van dat maatje niet kan zien — zonder definer zou de 10-telling te laag uitvallen — en profiles dicht is. Grenzen 30 en 10 als literals met commentaar dat ze uit CLUB-18 komen.

Sectie 10 — public.ensure_group_admin() returns trigger; trigger group_members_ensure_admin `after delete or update of role on public.group_members for each row`. Stappen: (1) lock de groepsrij `for update`; is die er niet meer (groep wordt net opgeheven en de cascade ruimt leden op) → return null; (2) bij TG_OP = 'UPDATE': als old.role = 'admin' en new.role <> 'admin' en er is geen enkele admin meer in old.group_id → last_admin; return null; (3) bij TG_OP = 'DELETE': is er geen lid meer → `delete from public.groups where id = old.group_id` (lege groep verdwijnt; groepsritten krijgen via de FK group_id = null, links cascaden); anders, is er geen admin meer → update group_members set role = 'admin' voor het lid met de oudste joined_at in die groep (tiebreak user_id oplopend, limit 1); return null. Commentaar: dekt verlaten, verwijderd door een beheerder, én account weg — `delete_own_account` verwijdert auth.users en de FK-cascade op group_members.user_id vuurt deze after-delete-trigger per rij (CLUB-19); security definer omdat wie vertrekt geen recht heeft een ander te promoveren; de lock voorkomt dat twee beheerders die tegelijk vertrekken elk de ander nog als beheerder zien. De promotie-update vuurt deze trigger opnieuw maar met old.role = 'member' en doet dan niets.

Sectie 11 — public.create_group(p_name text) returns uuid. auth.uid() null → not_authenticated. v_name := btrim(p_name); null of lengte buiten 1..60 → group_name_invalid. Insert in groups (name, created_by = auth.uid()) returning id; insert in group_members (group_id, user_id, role 'admin') — de guard-trigger telt mee, dus een 11e groep faalt met too_many_groups en rolt de groepsrij mee terug (één statement, atomisch, CLUB-01/CLUB-18). Return het id. Commentaar waarom rpc (keuze d uit de kop).

Sectie 12 — public.redeem_group_invite(p_code text) returns table (group_id uuid, group_name text). Zet `#variable_conflict use_column` bovenaan de body en kwalificeer ALLE kolomverwijzingen met een tabelalias (de out-kolom group_id botst anders met group_members.group_id). auth.uid() null → not_authenticated. Normaliseer de code met upper(btrim(p_code)). Zoek de invite met expires_at > now(); niet gevonden → invite_invalid. Is de aanroeper al lid → sla de insert over (niet `on conflict do nothing`: een before-insert-trigger vuurt ook bij een conflict en zou een bestaand lid van een volle groep group_full geven). Anders insert in group_members (group_id, user_id, role 'member'). Return de groep (id, name). Commentaar: security definer omdat de genodigde de groep nog niet kan lezen (keuze 1 uit 0002); rate limiting hoort bij epic #75, net als bij redeem_friend_invite (deferred).
