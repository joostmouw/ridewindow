<objective>
Rewrite the published privacy policy so it describes what the app will actually do once accounts ship. The current text is not merely incomplete — it makes four specific promises that become false: data stays on your device, no account required, no server-side storage, no data shared with third parties.

This matters beyond correctness. Google Play can flag or suspend an app whose declared data handling contradicts its behaviour, and the OAuth consent screen points at this exact URL. A policy that still promises device-only storage while the app writes to Postgres in Paris is the kind of contradiction that surfaces at review time, not before.

Output: a rewritten `docs/privacy-policy.html`, Dutch and English, at the unchanged URL, covering server-side storage, both sub-processors, EU residency, deletion and export.
</objective>

**The current file (55 lines) and what is wrong with it.** `docs/privacy-policy.html` is standalone HTML with inline `<style>`, no external assets, no build step — GitHub Pages serves `docs/` directly. Last updated June 21, 2026. Contact address in the file is `joost@fanalists.com`; keep that one, do not substitute a different address.

Statements that must go, because each becomes false:
- "Your data stays on your device. We do not collect, store, or share any personal information."
- "No account or login required"
- "No server-side storage of any user data"
- "No data shared with third parties"
- "All app data ... is stored locally on your device ... Uninstalling the app removes all data." (uninstalling no longer removes cloud data)

Statements that stay true and should be preserved: Open-Meteo receives coordinates for forecasts; Calendar is optional and read for availability; no analytics, no tracking, no advertising; not directed at children under 13.

**What must be newly disclosed:**

| | Detail |
|---|---|
| What is stored server-side | Profile settings (tolerances, ride lengths, theme, locale, location override, notification toggles), weekly availability pattern, planned rides. Only for signed-in users. |
| What is NOT stored server-side | The weather forecast cache and calendar-imported blocked hours — both stay on the device by design (SYNC-09, SYNC-10). Worth stating: it shows the disclosure is specific rather than blanket. |
| Where | Supabase, EU region — West EU (Paris), `eu-west-3`. |
| Sub-processors | **Supabase** (authentication, database, EU) and **Google** (Firebase Hosting for the web app; Google Calendar API when the user connects it; Google Sign-In for authentication). Two, not one. |
| Identity | Google Sign-In only. Signing in is optional; the app remains fully usable signed out, and signing out never deletes local data. |
| Deletion | Request by email to `joost@fanalists.com` with a fixed subject line. Removes the account and its stored rows. Feedback previously submitted is retained but de-identified. Must be usable after uninstalling. |
| Rights | Access, portability (export), erasure. Response within one month. Export supplied as JSON on request. |
| Retention | Rows removed on deletion; de-identified feedback retained indefinitely for scoring calibration. |

**Language.** Dutch and English on one page (CONTEXT.md D-13). Dutch first — the testers are Dutch — with English following under a clear heading, or a two-column/anchored layout if that reads better. Both versions must be complete; a Dutch summary pointing at an English body does not satisfy this. Set `<html lang="nl">` and mark the English section with `lang="en"`.

**Legal standing.** CONTEXT.md D-14: this is drafted by Claude, is not lawyer-reviewed, and that limitation is accepted. Write it plainly and accurately rather than imitating legalese — a clear, honest description of actual behaviour is both more useful and more defensible than borrowed boilerplate that describes practices this app does not have.
