<interfaces>
**`attemptLightweightAuthentication()` — google_sign_in 7.x, verified live against pub.dev (2026-07-26):** `GoogleSignIn.instance.attemptLightweightAuthentication({bool reportAllExceptions})` → `Future<GoogleSignInAccount?>?` — "Attempts to sign in a previously authenticated user with minimal interaction." This is the non-prompting mechanism D-11 requires: it resolves whichever Google identity the SDK can silently recall, or null, and never opens a picker or a consent screen. This is the *same* non-prompting shape `isCalendarConnected()` already uses via `authorizationForScopes()` — the two checks are siblings, not a new pattern.

**Why compare `.email`, not the Supabase uid:** `currentUserIdProvider` (Plan 19-01) resolves to a Supabase UUID, which has no relationship to a Google account identity. The comparison here is Google-identity-to-Google-identity: `authStateProvider`'s `User.email` (populated from the Google ID token's `email` claim during `signInWithIdToken`) against `CalendarService.currentGoogleEmail()`'s result. Both are Google account emails; the Supabase uid is irrelevant to this specific check.

**Existing Calendar row to extend, not replace** (`profile_screen.dart:698-714`): leading `Icon(Icons.calendar_month)`, title `s.googleCalendarLabel`, subtitle `_calendarStatusText(s)`, trailing a loading spinner / Disconnect `TextButton` / nothing, driven by `_calendarConnected` (`bool?`, set in `initState` via `_checkCalendarConnection()`). Add the mismatch warning as an additional line *below* the existing subtitle when connected, not as a replacement of the existing status text — a user must still see "Connected" alongside the warning, not one or the other.
</interfaces>
