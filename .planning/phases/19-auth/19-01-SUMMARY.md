## Decisions Made
- **`publishableKey` over `anonKey` in `Supabase.initialize()`:** `supabase_flutter` 2.16.0 deprecates the `anonKey` named parameter in favor of `publishableKey` (`effectiveKey = publishableKey ?? anonKey` internally -- same value works with either). Using the non-deprecated parameter avoided introducing a new `deprecated_member_use` analyzer warning on a file the plan's acceptance criteria required to stay clean. Purely a naming change; the JWT-format anon key from the dashboard is unaffected.
- **No new test file for `authStateProvider`'s internal logic:** the plan's own acceptance criteria for Task 3 state "no test yet exercises this provider, so this confirms no compile-time regression elsewhere" -- an explicit, already-reviewed acceptance bar. `Supabase.instance` is a singleton that only becomes usable after a real `Supabase.initialize()` call, so a meaningful unit test of the seed-then-merge behavior would need its own Supabase test-mode scaffolding not otherwise present in this codebase. Per `19-CONTEXT.md` D-20, real coverage arrives in Plan 19-05 via the existing provider-override pattern (override `authStateProvider` directly in widget tests for the account section), which is the acceptance criteria's own stated path. This was followed literally rather than expanded, to avoid building test infrastructure not requested by the plan.
