<objective>
Make AUTH-08 actually true, not just recorded for Phase 21: compare the newly signed-in Supabase uid against `account.lastSyncedUid` (a new local key), and when they differ, ask the user to keep or wipe — never guess.

This is deliberately built as a pure, SDK-free decision function first (`account_switch_resolver.dart`, mirroring the shape of `ARCHITECTURE.md` §5's full resolver, but scoped down to this phase's reality: there is no cloud data yet, only a local "have I seen this uid before" comparison). The uid storage this plan introduces is exactly the foundation Phase 21's real conflict resolver needs (`lastSyncedUid`, per `ARCHITECTURE.md` §5) — this plan does not build that resolver, only the local half.

Purpose: close the one AUTH requirement in this phase that is about data safety across accounts, not sign-in UX.

Output: `lib/domain/services/account_switch_resolver.dart` (new, pure), the switch dialog wired into `account_section.dart`'s sign-in completion step, and `resetToDefaults()`/`clearAll()` reset methods added to the two notifiers that don't yet have one.
</objective>

<interfaces>
**Scope fence, explicit:** this is the *local-only* half of what `ARCHITECTURE.md` §5 calls `resolveAccountSync`. That full resolver additionally compares cloud row existence and `updated_at` timestamps — none of which exist until Phase 21 creates the schema. This plan's `resolveAccountSwitch` takes exactly two inputs (`signedInUid`, `lastSyncedUid`) and returns exactly three outcomes. Do not attempt to build the cloud-aware version here — there is nothing to compare it against yet, and doing so would mean writing dead code against a schema that doesn't exist (violates the phase's "no database rows" fence).

**D-09's wipe scope, exactly:** profile settings (`ProfileNotifier`), weekly availability (`AvailabilityNotifier` — already has `clearAll()`), and planned rides (`PlannedRidesNotifier` — needs a new `clearAll()`). The Drift forecast cache is **never** touched by this plan — it is derived data (same reasoning already applied to `SYNC-09` in `ARCHITECTURE.md`).

**`ProfileNotifier.resetToDefaults()` — new method needed.** `profile_notifier.dart` currently has no "clear everything" method, only per-field setters. Read its `build()` method's default values (12.0/26.0/15.0/0.5 tolerances, `[2,3,5]` durations, `'system'` theme, system-language locale, null overrides) — `resetToDefaults()` must remove every one of the 11 `_key*` `SharedPreferences` keys it defines and then re-run the same default-construction logic `build()` already uses, so the resulting `UserProfile` is identical to what a fresh install would produce.
</interfaces>
