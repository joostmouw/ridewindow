`lib/app/router.dart` route paths (for direct-URL testing): `/welcome`, `/onboard`, `/home`, `/agenda`, `/rides`, `/profile`, `/availability`, `/detail`. No `usePathUrlStrategy()` call exists anywhere in the codebase (confirmed via repo-wide grep during planning) -- the app uses Flutter Web's default hash-based URL strategy (`.../#/profile`, not `.../profile`). This matters for how "direct URL load / page refresh" should be tested: the browser never sends the `#fragment` portion to the server, so Firebase Hosting only ever sees requests for the path before the `#` (almost always `/`). The rewrite rule is what stops a plain `GET /profile` (no hash) from 404ing, and `go_router` reading `window.location.hash` on boot is what makes a hash deep-link + hard-refresh restore the correct screen. Test BOTH: (a) curl a bare nested path with no hash to prove the rewrite rule, and (b) a real browser hard-refresh on a hash deep-link to prove client-side route restoration.
