<objective>
Fix a real, already-existing standalone-mode navigation dead end (PWA-04): `AvailabilityScreen`'s three `AppBar`s use an unconditional `BackButton()`, but the screen is reachable via `context.go('/availability?from=onboarding')` from `OnboardingScreen` — `context.go()` REPLACES the navigation location rather than pushing, so `Navigator.canPop()` is `false` on arrival and the back button, while visually present, does nothing when tapped. In a standalone installed PWA there is no browser chrome to fall back on, so this is a genuine dead end today, not a hypothetical one. `RideDetailScreen`'s auto-implied back arrow and `router.dart`'s invalid-`DetailArgs` error page have the same latent gap for a cold-launch/reload-with-no-history case (per D-05's generic audit instruction).

Purpose: No screen in standalone mode may rely on a browser back button that does not exist.
Output: One shared `SafeBackButton` widget, wired into the 3 places above.
</objective>
