<objective>
Wire the two "single-row-per-user, LWW-comparable" domains — profile and availability — to the cloud, per `.planning/research/ARCHITECTURE.md` §7 step 5. This is where SYNC-01/02 stop being schema-only (plan 21-02) and become real: every local save enqueues a cloud write via Wave 2's outbox, and every foreground brings the cloud's state back in if it is newer.

**Design clarification beyond ARCHITECTURE.md's illustrative §2 snippet:** ARCHITECTURE.md §2 shows `ProfileRepository.writeCloud()` calling `_cloud.from('profiles').upsert(...)` directly. §4a is the authoritative statement of what actually happens: *"Every local write... the cloud write is enqueued in the outbox and drained."* This plan follows §4a — repositories enqueue into the outbox (Drift-only dependency, no `SupabaseClient`), they never call Supabase directly. This keeps `profile_repository.dart`/`availability_repository.dart` free of any `package:supabase_flutter` import, which matters because both files are reachable from `lib/platform/background_task.dart` (REG-05) — a direct import there would break the existing `test/structure/background_task_no_supabase_test.dart`.

**SYNC-07's "never block cold start" requirement drives a hard separation:** `ProfileNotifier.build()`/`AvailabilityNotifier.build()` only ever read local storage — the actual Supabase read (for pulling a newer cloud row on foreground) lives in a separate `CloudReconcileService` + `CloudSyncReconciler`, triggered from the app's *existing* foreground hook (`HomeScreen.didChangeAppLifecycleState`, already wired for weather refresh since Phase 14), called without `await` in the UI path.

Purpose: make a signed-in user's settings and weekly availability actually reach Postgres and come back on another device, without ever making the app wait on the network to open.

Output: `toRow()`/`toRecurringRow()` pure conversion functions (the exact row-shape contract), outbox-aware repositories, a `CloudReconcileService`, and the foreground reconcile wiring.
</objective>

**`public.availability`'s `recurring` jsonb shape — `{"<weekday>-<hour>": "<blocktype>"}`, string keys, string values, calendar entries excluded (SYNC-10):**

```dart
// lib/domain/services/availability_key.dart additions
/// weekday(1-7) * 24 + hour(0-23) is already how BlockedHours indexes
/// recurring entries internally (see _slotOf) — this is that same formula,
/// made public and reusable for the cloud row shape.
int recurringSlotKey(DateTime canonicalHour) =>
    canonicalHour.weekday * 24 + canonicalHour.hour;

/// SYNC-10: BlockType.calendar entries are date-specific and never synced —
/// same reasoning already applied to the Drift forecast cache (SYNC-09).
/// Only work/custom survive into the cloud row.
Map<String, dynamic> toRecurringRow(Map<DateTime, BlockType> hours) {
  final recurring = <String, String>{};
  for (final entry in hours.entries) {
    if (entry.value == BlockType.calendar) continue;
    final key = canonicalHourKey(entry.key);
    recurring['${key.weekday}-${key.hour}'] = entry.value.name;
  }
  return recurring;
}

/// Reconstructs a local-storage-shaped map from a pulled cloud `recurring`
/// row. Since the cloud format is weekday+hour abstract (no concrete date),
/// each slot is materialized onto [weekAnchor]'s week (defaults to the
/// current week's Monday) — matching how existing presets seed a reference
/// week (buildPreset's weekStart.weekday == DateTime.monday convention).
Map<DateTime, BlockType> fromRecurringJson(
  Map<String, dynamic> recurring, {
  DateTime? weekAnchor,
}) {
  final now = weekAnchor ?? DateTime.now();
  final monday = DateTime(now.year, now.month, now.day)
      .subtract(Duration(days: now.weekday - 1));
  final result = <DateTime, BlockType>{};
  for (final entry in recurring.entries) {
    final parts = entry.key.split('-');
    if (parts.length != 2) continue;
    final weekday = int.tryParse(parts[0]);
    final hour = int.tryParse(parts[1]);
    if (weekday == null || hour == null) continue;
    final date = monday.add(Duration(days: weekday - 1, hours: hour));
    final blockType = BlockType.values.byName(entry.value as String);
    result[date] = blockType;
  }
  return result;
}
```

class CloudReconcileService {
  CloudReconcileService(this._client);
  final SupabaseClient _client;

  Future<({UserProfile profile, DateTime updatedAt})?> readCloudProfile(String userId) async {
    final row = await _client.from(kProfilesTable).select().eq('user_id', userId).maybeSingle();
    if (row == null) return null;
    return (profile: UserProfile.fromRow(row), updatedAt: DateTime.parse(row['updated_at'] as String));
  }

  Future<({Map<DateTime, BlockType> hours, DateTime updatedAt})?> readCloudAvailability(String userId) async {
    final row = await _client.from(kAvailabilityTable).select().eq('user_id', userId).maybeSingle();
    if (row == null) return null;
    return (
      hours: fromRecurringJson(row['recurring'] as Map<String, dynamic>),
      updatedAt: DateTime.parse(row['updated_at'] as String),
    );
  }
}

**`CloudSyncReconciler` — the fire-and-forget foreground entry point:**

```dart
// lib/providers/cloud_sync_reconciler_provider.dart (or inline in an existing provider file — planner's choice, keep it small)
@riverpod
CloudSyncReconciler cloudSyncReconciler(Ref ref) => CloudSyncReconciler(ref);

class CloudSyncReconciler {
  CloudSyncReconciler(this._ref);
  final Ref _ref;

  /// Non-interactive, silent pull-if-newer — deliberately NOT the same as
  /// resolveAccountSync (that stays exclusively a sign-in-time concern,
  /// wired in a later plan). This never prompts; it only ever adopts the
  /// cloud row when it is unambiguously newer than local by more than a
  /// small margin, matching resolveAccountSync's own 5-second noop band so
  /// the two mechanisms never disagree about what counts as "changed."
  Future<void> reconcileOnForeground() async {
    final user = _ref.read(authStateProvider).value;
    if (user == null) return;
    final client = Supabase.instance.client;
    final service = CloudReconcileService(client);

    final profileRepo = await _ref.read(profileRepositoryProvider.future);
    final cloudProfile = await service.readCloudProfile(user.id);
    if (cloudProfile != null) {
      final localMs = profileRepo.readUpdatedAt();
      final local = localMs == null ? null : DateTime.fromMillisecondsSinceEpoch(localMs);
      if (local == null || cloudProfile.updatedAt.difference(local) > const Duration(seconds: 5)) {
        await profileRepo.save(cloudProfile.profile, stamp: false);
        await profileRepo.stampUpdatedAt(cloudProfile.updatedAt);
        _ref.invalidate(profileProvider);
      }
    }
    // Same pattern for availability, using availabilityRepositoryProvider / availabilityProvider.
  }
}
```

Wrap the whole method body in a try/catch that swallows and `debugPrint`s any error — a failed reconcile must never crash the app or surface an error to the user (matches this codebase's existing pattern for non-critical background work, e.g. `background_task.dart`'s widget-update try/catch).
