<objective>
Wire `planned_rides` to the cloud — the one domain whose data shape (a growable list of independent rows, not a single mutable blob) means it deliberately does NOT go through `resolveAccountSync` (plan 21-01) or a conflict dialog (plans 21-06/21-07 scope those strictly to profile+availability, per D-04/D-05's explicit two-dialog enumeration and MIG-04's explicit "profile and availability" wording).

**The design decision this plan makes, stated plainly (no source document specifies planned-rides' sync algorithm beyond "stored in the cloud" and "one row per ride" — this is reasoned within the locked constraints, not an invented feature):** each ride is keyed by a deterministic `ride_id` (ARCHITECTURE.md §3's own words: "derive deterministically from `start.toIso8601String()`... makes upsert-on-retry safe"). Since rides don't have a mutable "current state" to diverge on — a ride either exists or it doesn't — the correct reconciliation on foreground is a **union merge**: any ride present on either side ends up on both, converging without ever silently dropping one a different device already planned. This is safe specifically *because* availability's "never auto-union" exclusion (REQUIREMENTS.md Out of Scope) is about **exclusionary** data (a schedule getting more available than intended) — planned rides are **additive** data with no such failure mode; adding a ride nobody objects to is harmless.

Purpose: complete SYNC-03, and give plan 21-06/21-07's sync-status indicator (SYNC-06) a third domain contributing to "pending vs synced," alongside profile/availability from plan 21-04.

Output: `PlannedRide.rideId`/`toRow()`/`fromRow()`, a `PlannedRidesRepository` that enqueues one outbox row per ride add/remove, and a `reconcilePlannedRides()` extension to plan 21-04's `CloudSyncReconciler`.
</objective>

**`PlannedRidesRepository` gains `add()`/`remove()` — moved down from the notifier, which currently builds the next list and calls `save()` itself.** This is a deliberate consolidation: the repository already owns dedup/sort/filter conventions (`readLocal()`'s existing sort-by-start), and per-ride outbox enqueueing belongs next to that same list-mutation logic, not duplicated into the Riverpod layer.

```dart
class PlannedRidesRepository {
  PlannedRidesRepository(this._prefs, {SyncOutboxDao? outbox, this.userId}) : _outbox = outbox;
  final SyncOutboxDao? _outbox;
  final String? userId;
  // ... existing kPlannedRidesKey/kUpdatedAtKey/readLocal()/save()/readUpdatedAt() unchanged ...

  /// Moved from PlannedRidesNotifier.add() — same dedup-by-start/end check,
  /// same sort-by-start. Additionally enqueues one 'upsert' outbox row for
  /// exactly this ride when signed in.
  Future<void> add(PlannedRide ride) async {
    final current = readLocal();
    if (current.any((r) => r.start == ride.start && r.end == ride.end)) return;
    final next = [...current, ride]..sort((a, b) => a.start.compareTo(b.start));
    await save(next);
    if (_outbox != null && userId != null) {
      await _outbox!.enqueueOrCoalesce(
        entity: kOutboxEntityPlannedRide,
        entityKey: '${userId!}:${ride.rideId}',
        operation: 'upsert',
        payload: jsonEncode(ride.toRow(userId!)),
      );
    }
  }

  /// Moved from PlannedRidesNotifier.remove(). Enqueues a 'delete' outbox
  /// row for exactly this ride — the payload is '{}', since the drain step
  /// derives the delete filter (user_id + ride_id) from entityKey, not payload.
  Future<void> remove(PlannedRide ride) async {
    final current = readLocal();
    final next = current.where((r) => r.start != ride.start || r.end != ride.end).toList();
    await save(next);
    if (_outbox != null && userId != null) {
      await _outbox!.enqueueOrCoalesce(
        entity: kOutboxEntityPlannedRide,
        entityKey: '${userId!}:${ride.rideId}',
        operation: 'delete',
        payload: '{}',
      );
    }
  }

  /// Used only by the foreground reconciler (plan 21-05's CloudSyncReconciler)
  /// to push a ride that exists locally but not yet in the cloud, without
  /// re-running add()'s dedup/save() (it is already in the local list).
  Future<void> enqueueUpsert(PlannedRide ride) async {
    if (_outbox == null || userId == null) return;
    await _outbox!.enqueueOrCoalesce(
      entity: kOutboxEntityPlannedRide,
      entityKey: '${userId!}:${ride.rideId}',
      operation: 'upsert',
      payload: jsonEncode(ride.toRow(userId!)),
    );
  }
}
```

```dart
Future<void> reconcilePlannedRides() async {
  final user = _ref.read(authStateProvider).value;
  if (user == null) return;
  final repo = await _ref.read(plannedRidesRepositoryProvider.future);
  final cloudRows = await CloudReconcileService(Supabase.instance.client).readCloudPlannedRides(user.id);
  final local = repo.readLocal();
  final localIds = local.map((r) => r.rideId).toSet();
  final cloudIds = cloudRows.map((r) => r['ride_id'] as String).toSet();

  final merged = <String, PlannedRide>{
    for (final r in local) r.rideId: r,
  };
  for (final row in cloudRows) {
    final ride = PlannedRide.fromRow(row);
    merged.putIfAbsent(ride.rideId, () => ride);
  }

  // Converge: push anything local-only up to the cloud.
  for (final ride in local) {
    if (!cloudIds.contains(ride.rideId)) {
      await repo.enqueueUpsert(ride);
    }
  }

  final sorted = merged.values.toList()..sort((a, b) => a.start.compareTo(b.start));
  if (sorted.length != local.length || !localIds.containsAll(merged.keys)) {
    await repo.save(sorted, stamp: false);
    _ref.invalidate(plannedRidesProvider);
  }
}
```
