<objective>
Make a planned ride survive the cloud without splitting in two. Found on device 2026-08-05
(`MANUAL-VERIFICATION-21.md`, device session 4): Joost tapped "Schedule" once and "My Rides"
showed the same ride twice — same date, same 12:00–15:00 window, same score, two cards.

The cause is that `rideId` is timezone-sensitive:

```dart
String get rideId => start.toIso8601String().replaceAll(RegExp(r'[:.]'), '-');
```

| Stage | Value |
|-------|-------|
| Created locally (local `DateTime`) | `2026-08-08T12:00:00.000` → rideId `2026-08-08T12-00-00-000` |
| Written to Postgres | `start_at` is `timestamptz`; an offsetless string is read in the session zone and stored as an instant |
| Read back via PostgREST | `2026-08-08T12:00:00+00:00` → `DateTime.parse` returns a **UTC** `DateTime` |
| rideId of that object | `2026-08-08T12-00-00-000` **`Z`** — a different key |

`CloudReconcileService.mergePlannedRides()` dedupes on `rideId`. Two keys, so the union keeps
both. Both cards render "12:00–15:00" because the formatter prints the `DateTime`'s own fields
without converting, so the duplicate is invisible in the UI and obvious only in the data.

`PlannedRidesRepository.add()`'s own guard misses it for the same underlying reason: it compares
`r.start == ride.start`, and Dart's `DateTime.==` is true only when both the instant **and** the
`isUtc` flag match.

Scope is narrow: make ride identity canonical, make the dedup instant-based, and let existing
duplicates heal themselves. Do not redesign planned-ride storage.
</objective>

<context>
**The codebase already knows this rule and did not apply it here.**
`lib/domain/services/availability_key.dart:8` carries the comment
*"een `andere` sleutel — `DateTime.==` vergelijkt ook `isUtc`"*. That lesson was learned for the
availability grid (quick task 260725-knl) and never carried across to planned rides. Treat that as
the finding: the invariant exists in prose in one file instead of in a shared helper or a test that
covers every keyed domain object.

**Why the whole suite is green.** `test/domain/models/planned_ride_row_test.dart:37` asserts
`fromRow(toRow(userId))` round-trips. It passes, because `toRow` emits an offsetless string and
`DateTime.parse` turns that back into a local `DateTime`. The round trip is closed **inside Dart**.
Postgres is what breaks it: `timestamptz` normalizes, and PostgREST returns `+00:00`. The test
never sees the wire format it claims to cover.

`test/services/cloud_reconcile_service_test.dart:84` has the same blind spot from the other side —
its `ride()` helper builds both the local and the cloud side with
`DateTime.parse('2026-08-11T09:00:00.000')`, so both are local and the split can never appear.

**This is the fourth instance of one pattern.** 21-10 asserted the call site existed. 21-11 asserted
the call reached its work. 21-12 asserted the payload was a legal row. Each test stopped one layer
short of the boundary that actually broke. This one stops at Dart's edge instead of the database's.
The new test must start from a string that Postgres would really return.

**Changing rideId orphans the existing cloud rows — plan for it.** After this fix, a 12:00 local
ride (10:00 UTC) keys as `2026-08-08T10-00-00-000Z`. The rows already in `public.planned_rides`
carry `2026-08-08T12-00-00-000` and, for the duplicated ones, `2026-08-08T12-00-00-000Z`. Neither
matches the new canonical id, so a plain fix would pull those rows back in and re-create the
duplicate under a third key. The reconcile path must therefore repair rows it finds in a
non-canonical shape rather than assume a clean database.

**No server-side work.** `CLAUDE.md` allows exactly one `plpgsql` function and no other server-side
code, so the repair is client-side inside the existing foreground reconcile — a delete of the
stale-keyed row plus an upsert of the canonical one, through the outbox that already exists. No
SQL migration, no Edge Function, no manual dashboard surgery.

**Local duplicates too.** The device's SharedPreferences list already holds both copies. The fix
must collapse them on read, not only prevent new ones, or Joost's "My Rides" stays wrong on a build
that is technically correct.
</context>
