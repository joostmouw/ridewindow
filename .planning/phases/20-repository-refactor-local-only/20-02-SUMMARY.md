# Phase 20 Plan 02: Profile Repository Refactor Summary

**ProfileRepository now owns all twelve `profile.*` SharedPreferences keys plus `profile.updatedAt`; ProfileNotifier is a thin Riverpod layer over it, and the sign-in name-autofill uses a dedicated non-stamping write path that answers Phase 19's deferred D-07 question in code.**

## Accomplishments
- `UserProfile` (with its sentinel-copyWith pattern) lives in plain-Dart `lib/domain/models/user_profile.dart`; every existing import site keeps working unchanged via a re-export from `profile_notifier.dart`.
- `ProfileRepository` is the single source of truth for all twelve `profile.*` keys — identical key strings, types, and defaults to the pre-refactor code (D-01), including the durations-corruption filter and the `remove()`-not-empty-string behavior for `locationOverride`/`userName`.
- `ProfileNotifier` is now a thin layer: `build()` and all nine mutators (`updateTolerances`, `toggleDuration`, `setLocale`, `setTheme`, `setLocationOverride`, `setUserName`, `setNotifEveningBefore`, `setNotifMorningOf`, `setNotifWeeklyDigest`) delegate to the repository with unchanged signatures and logic. `resetToDefaults()` calls `repo.resetToDefaults()` (which now also clears `profile.updatedAt`) and rebuilds state via the same construction logic as `build()`.
- **D-07 answered in code**, not just documented: a new `setUserNameFromSignIn(name)` method writes via `repo.save(next, stamp: false)`. `account_section.dart`'s sign-in autofill now calls it instead of `setUserName`, while the two user-typed call sites (`home_screen.dart:296`, `profile_screen.dart:203`) are untouched and still stamp.
- New `test/data/repositories/profile_repository_test.dart` covers the risk the wider suite doesn't: reading a pre-existing installation's twelve values back exactly, fresh-install defaults, locale-default precedence (systemLanguageCode vs. saved locale), corrupt-durations fallback, null-clears-the-key behavior, and D-07's stamp/no-stamp write paths.

## Decisions Made
